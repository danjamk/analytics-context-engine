# Reporting standards

> How I want deliverables to look and read. Read before producing any report, chart, or
> shareable artifact. Recipes cite this file; they do not repeat it.
> Standards are preferences. They never override a correctness rule: presentation is my call,
> accuracy is not.
> Last verified: YYYY-MM-DD

## Format and delivery

- Default: <e.g. one self-contained HTML file, data embedded, no network dependency>
- Other formats and when: <e.g. Markdown summary for chat; PDF only when asked>
- Where it goes: <e.g. reports/ in the domain repo; a document portal for anything shared>

## Section order

1. <e.g. one orientation line: what this is, period, as-of>
2. <e.g. the conclusion>
3. <e.g. the main chart>
4. <e.g. notes and caveats, collapsible>
5. <e.g. the data table, collapsible>

## Conclusions and recommendations

- Placement: <e.g. first, above any chart>
- Form: <e.g. one sentence each; a number in every one>
- Recommendations: <e.g. numbered; each names the action, the owner, and the evidence>
- Uncertainty: <e.g. say PROVISIONAL in the line itself, not in a footnote>

## Charts

- <e.g. one message per chart, stated in its title>
- <e.g. no dual axes; start bars at zero>
- Colors: <palette or rule>

## Interactivity

- <e.g. tooltips on every mark, with the exact value and its definition>
- <e.g. a filter wherever a definition is contested, showing both readings>
- <e.g. notes and data tables collapsible, closed by default>

## Provenance and caveats

- <e.g. grain, population, source, as-of under each figure>
- <e.g. triggered caveats next to the figure they affect>

## Writing

- <e.g. plain words, short sentences, no editorial prose above the chart>
